# 设备设置-高级管理-协议控制实机缺陷证据

测试时间：2026-07-21；设备版本：4.0.307 Enterprise Build202607211006。

## 复现条件

1. 通过页面 `/#/equipmentSetting/advancedManagement` → `协议控制` 选择“性能模式”，确认“我知道了”。
2. 页面请求为：`POST /Action/call`，`func_name=core_control`、`action=save`、`param={"mode":0}`。
3. 读取数据库和运行态：

   ```sh
   sqlite3 /etc/mnt/ikuai/config.db \
     'select id,mode,dpi,quic,https,appid_load from forward_mode_config where id=1'
   cat /proc/ikuai/stats/ik_features_status
   pidof ik_url_auditd
   test -e /tmp/iktmp/audit.open_url_record && echo 1 || echo 0
   ```

## 预期与实测

页面性能模式说明为关闭 DPI、访问记录和应用层审计。实测数据库正确变为：

```text
1|0|0|0|0|0
```

同时 DPI、L4 DPI、HTTPS 和 appid_load 均为 `disable`，相同唯一 HTTP 流量经
`192.168.148.1` 转发成功、SNAT 正常，且没有 DPI 识别和访问记录。

但是以下三项仍保持开启：

```text
audit : enable
pidof ik_url_auditd -> 有进程
/tmp/iktmp/audit.open_url_record -> 存在
```

执行 `/usr/ikuai/script/core_control.sh init` 后上述三项仍未关闭。综合用例因此
严格失败以下断言：

- `feature.audit` 应为 `disable`，实测 `enable`；
- `ik_url_auditd` 应停止，实测仍运行；
- `audit.open_url_record` 应删除，实测仍存在。

这不是测试降级项：L5 正反流量、数据库、DPI、访问记录、LAN 转发、SNAT、管理
连接和 finally 恢复均已分别验证通过。建议产品修复 `core_control.sh save/init`
在性能模式下同步调用审计关闭/URL 访问记录停止逻辑，或修正页面说明。

最终独立复核（恢复到平衡模式）：`mode=1,dpi=1,quic=0,https=1,appid_load=1`；
DPI/审计开启、QUIC关闭；管理连接、`192.168.148.2` SNAT、`192.168.148.5`
独立会话正常；无 `IKPC_` 测试文件、进程、路由、审计索引或记录残留。
