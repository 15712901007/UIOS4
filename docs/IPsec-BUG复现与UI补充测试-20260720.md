### BUG-010 复现铁证（纯页面，单机必现）

前端允许范围 > 后端接受范围，三处不一致：

| 字段 | 前端（实测） | 后端（实测） | 提交边界值结果 |
|---|---|---|---|
| 备注 comment | 无 maxLength | ≤80 | 输 100 字符 → 3001 `参数错误: comment` |
| SA 流量上限 ipsec_sa_bytes | placeholder `42949667295` | ≤4294967295 | 输 4294967296 → 3001 `参数错误: ipsec_sa_bytes` |
| 预共享密钥 secret | 无 maxLength | 1-128 | 输 129 字符 → 3001 `参数错误: secret` |

JIRA：`【网络配置-IPsec VPN】隧道策略部分字段前端允许输入范围大于后端，页面可输入但保存被拒`。归属前端，建议备注 maxLength=80、SA 流量上限 max=4294967295、PSK maxLength=128。

## 二、UI 补充测试（参考 IKOS-6952 已提单的测试方法）

### 测试方法对比
- **IKOS-6952 已提单方法**：用户操作 → 看前端表现（输入校验/提示文案/默认值/切换交互/列表详情显示/确认弹窗文案/协议行为）。31 个 IPsec 单几乎全是这个视角。
- **本轮采用同样方法**：系统走 IPsec UI，聚焦他们未覆盖的维度（列表刷新、编辑回显、复制、启停刷新、IKE提议校验）。

### 测试覆盖与结果

| 维度 | 操作 | 结果 |
|---|---|---|
| 列表显示 | show 返回 vs 页面渲染 | 正常 |
| 编辑回显 | 编辑策略看各字段 | PSK 回显真实值（password 框掩码）；策略名称/协商模式/IP地址类型 disabled（设计） |
| 复制功能 | 复制 150 | 预填源策略数据到新建表单，改名保存正常 |
| 启停后列表刷新 | 停用 uitest01 | **正常**：操作按钮即时"停用↔启用"切换（对比 GRE 6984/6985，IPsec 无此问题） |
| 停用确认弹窗文案 | 停用弹窗 | "是否要停用这条策略"，正常（对比 IKOS-6957 启用弹窗"启动"用词问题，停用侧正常） |
| IKE提议校验 | proposal 边界值 | sa_lifetime 有范围（0/超大拒）、priority 负数拒、中文名后端允许 |

### 观察记录（非 BUG，备查）

1. **show 接口明文返回 PSK**：`/Action/call show ipsec2_policy` 返回 `secret` 明文（实测 150 的 `rsx890426`、uitest01 的 `uitestpsk001`）。与 BUG-004 同类（路由器单 admin 场景），判定不算 BUG。
2. **编辑表单 PSK 回显明文到 DOM**：input `type=password` 掩码显示，但 DOM `value` 是真实 PSK（实测 valueLen=9，"rs***"）。编辑其他字段保存时会用回显明文重新提交，回显正确则无影响。
3. **proposal 中文名后端允许**：API add proposal 中文名 code:0 成功（后端允许）。IKOS-6955 已提前端中文提示问题，建议前后端中文命名规则统一。
4. **API 建策略页面列表不自动刷新**：API 绕过页面建策略后，页面列表不自动显示，需复制/启停等 UI 操作触发刷新。属 SPA 正常行为（API 非用户路径），不算 BUG。

### 结论

本轮按 IKOS-6952 已提单的 UI 测试方法，系统走了 IPsec 页面的列表/编辑/复制/启停/IKE提议等维度，**未发现新的、纯页面稳定可复现的 BUG**。已提的 31 个 IPsec 单 + 本次 BUG-010 已覆盖主要 UI 问题。其余深层协议/架构类（003/005/006/008/009）页面触发不到或需 SSH/抓包验证，不适合作为"用户可复现 BUG"提单。
