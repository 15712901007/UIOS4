# JIRA：MAC限速停用/删除后底层规则不清理（简洁版）

| 项 | 值 |
|---|---|
| 设备/固件 | IK-G2606-MXP / 4.0.303 |
| 设备IP | 10.66.0.45 |
| 模块 | 网络配置 → 终端限速 → MAC限速（mac_qos） |
| 提交人 | 戎士显 |
| 日期 | 2026-07-30 |

## 标题
【IK-G2606-MXP 4.0.303】MAC限速规则停用或删除后，iptables规则与ipset成员不清理，限速持续生效无法取消

## 问题描述（简洁）
MAC限速规则在web页面**停用**（或**删除**）后，底层 iptables 的 MAC_QOS 链规则和 ipset（`_mac_qos_1`）成员均**不清理**，规则按旧值持续生效，导致"停用/删除MAC限速"功能失效、限速无法取消。而同类的 IP限速(simple_qos) 停用后会正常清理 iptables 规则，两者行为不一致。此外，编辑(edit)改限速值时规则**累加**而非替换，导致 MAC_QOS 链出现多条规则并存。

## 复现步骤
1. Web 网络配置→终端限速→MAC限速，新增规则：MAC=D4:20:00:B1:45:EC，下行 3 MB/s，保存
2. SSH 查（正常下发）：
   - `iptables -S MAC_QOS | grep byteslimit` → 有规则
   - `ipset list _mac_qos_1 | grep Members` → 有 D4:20:00:B1:45:EC
3. 编辑该规则下行值改为 6 MB/s 再保存 → SSH 查 MAC_QOS 链出现**两条**规则（6144 与 3072 并存，累加）
4. Web **停用**该规则 → SSH 再查 iptables 与 ipset
5. （对照）Web 停用一条 IP限速规则 → SSH 查 IP_QOS

## 实际结果
- **停用**MAC限速后：
  - iptables MAC_QOS 规则**不清理**（仍存在，含历史累加的多条）
  - ipset `_mac_qos_1` 成员**不清空**（D4:20:00:B1:45:EC 仍在）
  - 残留规则继续生效：实测停用IP限速+停用MAC限速后，下行仍被限至 **13.6 Mbps**（本应不限速）
- **删除**MAC限速后：iptables 规则、ipset 成员同样**不清理**
- **对照**IP限速停用：iptables IP_QOS 规则数 1→**0**（正常清理）

| 操作 | IP限速停用后 | MAC限速停用后 |
|---|---|---|
| iptables 规则 | 0 条（已清理）✓ | 多条（残留+累加）✗ |
| ipset 成员 | 清空 ✓ | MAC地址仍在 ✗ |
| 下行实测 | 不限速 ✓ | 仍被限 13.6 Mbps ✗ |

## 预期结果
- MAC限速停用/删除后，应清理对应 iptables MAC_QOS 规则和 ipset `_mac_qos_1` 成员，停止限速（与 IP限速行为一致）
- 编辑改值应替换旧规则，不应累加

## 证据（关键命令输出）
```
# 停用后仍残留（bytelimit 6144 为旧值，3072 为新值，两条并存）
-A MAC_QOS -m set --match-set mac_qos_1 dst ... -m byteslimit --bytelimit 6144 ... -j DROP
-A MAC_QOS -m set --match-set mac_qos_1 dst ... -m byteslimit --bytelimit 3072 ... -j DROP
# ipset 成员未清空
ipset list _mac_qos_1 → Members: D4:20:00:B1:45:EC
```
临时手动清理（可恢复，但不应依赖手动）：
```
iptables -F MAC_QOS; ipset flush _mac_qos_1; ipset flush mac_qos_1
sqlite3 /etc/mnt/ikuai/config.db "DELETE FROM mac_qos;"
```

## 根因（开发参考）
mac_qos 的停用/删除处理逻辑未对齐 simple_qos 的 iptables/ipset 清理动作（simple_qos 停用会清理 IP_QOS 规则，mac_qos 缺失该清理）；且 edit 改值走"追加"而非"替换"，导致规则累加。建议 mac_qos 的 disable/del/edit 复用 simple_qos 的清理与刷新逻辑。
