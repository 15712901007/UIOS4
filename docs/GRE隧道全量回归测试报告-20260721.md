## 4. 本轮发现/复测 BUG（含证据与修复建议）

### BUG-N1【严重·Blocker·新发现】IPv6 GRE 创建必败（ip6gre 不接受 nopmtudisc）
- **前置**：被测 150 多线负载，进入 虚拟专网→GRE 新建 IPv6 GRE（no_fragment 默认 0）。
- **复现**：UI 新建 IPv6 GRE（合法 src/dst/tunnel_addr）→ 保存 → 提示"GRE隧道下发失败，请检查内核模块和地址配置"。
- **预期**：IPv6 GRE 创建成功（接口 UP，ip6gre remote/local 正确）。
- **实际**：100% 失败。`gre_tunnel.sh` v6 下发段 `[ "$no_fragment" = "0" ] && cmd+=" nopmtudisc"` 对 ip6gre 也加 nopmtudisc，但 **ip6gre 不接受 nopmtudisc**。
- **证据**：
  - `[router] ip -6 tunnel add greX mode ip6gre remote <peer> local <router> ttl 255 nopmtudisc` → `Error: either "name" is duplicate, or "nopmtudisc" is a garbage.` RC=255
  - 对照：去掉 nopmtudisc → RC=0，接口 UP，`ip -d link show` 含 `ip6gre remote ... local ... hoplimit 255` ✓
  - no_fragment=1（不加 nopmtudisc）时脚本 add 成功（DB enabled=yes + ip6gre UP）
- **影响**：**全部 IPv6 GRE 功能不可用**（创建即失败）。双栈 GRE 仅 IPv4 可用。
- **修复建议**：v6 分支不加 nopmtudisc（ip6gre 无此参数；PMTU 行为由 encaplimit 等控制）。

### BUG-N2【中·前后端不一致】gre_key=4294967296 经 WEB/API 越界被接受（CLI 拒）
- **前置/复现**：UI 新建 GRE，GRE Key 填 `4294967296`（=2³²，超 32 位 max 4294967295）→ 保存。
- **预期**：越界拒绝（脚本校验 `gre_key <= 4294967295`）。
- **实际**：WEB/API **接受并落库**（实际 gre_key=4294967295，被截断/clamp）。脚本 CLI `add gre_key=4294967296` 报 `参数错误:gre_key` 正确拒绝。
- **证据**：`sqlite3 ... gre_tunnel` 实际 gre_key=4294967295；CLI RC=1 `参数错误:gre_key`。
- **影响**：前后端校验不一致，32 位溢出风险。
- **修复建议**：WEB/API 层补 gre_key ≤4294967295 校验，与 CLI 一致。

### BUG-N3【中·前后端不一致】tos=256 经 WEB/API 越界被接受（CLI 拒）
- **复现**：UI Tos 填 `256`（>255）→ 保存。
- **预期**：拒绝（`tos <= 255`）。
- **实际**：WEB/API 接受并落库（实际 tos=255，clamp）。CLI 报 `参数错误:ttl` 路径相关校验拒绝。
- **证据**：DB 实际 tos=255。
- **影响/建议**：同 N2，WEB/API 补 tos ≤255 校验。

### BUG-N4【中·前后端不一致】no_fragment=0+ttl=64 经 WEB/API 未强制脚本约束
- **复现**：UI no_fragment=0(允许分片) + ttl=64 → 保存。
- **预期**：脚本校验 `[no_fragment==0]&&{ttl==0}` 要求 no_fragment=0 时 ttl=0 → 应拒。
- **实际**：WEB/API 接受并落库（实际 ttl=0，被改写）。脚本约束未在 WEB/API 强制。
- **证据**：DB 实际 ttl=0（用户填 64 被静默改为 0）。
- **影响/建议**：WEB/API 与脚本约束语义对齐；或前端联动禁用 ttl（已禁用）+ 后端拒绝越权值。

### BUG-R1【中·回归复现】keepalive 内核不生效
- **复现**：新建 GRE 开 keepalive(周期10/次数3) → `ip -d link show` 无 keepalive 字段。
- **根因**：`gre_tunnel.sh` 用 `ip tunnel change <iface> keepalive N M`，内核 5.10 ip_gre/iproute2 不支持 keepalive 参数 → 静默失败（`2>&1` 吞错），DB keepalive=1 形同虚设。
- **影响**：对端失联隧道不会 down。
- **建议**：用户态周期 ping 联动 up/down，或下发失败明确报错/前端禁用。

### BUG-R2【中·回归复现】IPv4 GRE 选路不绑源接口（源 wan3 走 wan1）
- **证据**：GRE 源=10.66.0.27(wan3)，`ip route get 10.66.0.56` → `dev wan1 src 10.66.0.150`（源/口不一致）。L5 数据面仍通（多线负载兜底），但选路口与配置源不符。
- **建议**：源地址选路绑定出口接口。

### BUG-R3【轻·回归复现】批量连续新增部分下发失败
- **复现**：已有 1 条 GRE，连续新建第 2 条 → "GRE 隧道下发失败"（run5: gre811）。
- **建议**：排查多 GRE 并发/资源竞争或 rt_tables/iface_band 累积。

### BUG-R4【轻·回归复现】删除后 UI 列表不自动刷新
- **复现**：删除 GRE 确认后，列表不立即移除（需 reload）。`delete_rule` 内部已 reload 兜底。

### BUG-R5【轻·回归复现】搜索不生效 / 清空搜索不恢复
- **复现**：搜索框输入接口名 → 列表未过滤；清空 → 未恢复全部。

### BUG-R6【轻·回归复现】帮助 popup 未打开
- **复现**：点"帮助"→ 无 popup（timeout）。
